# Аналитика руководителя

`/analytics` показывает все активные показатели доступных действующих операторов.
Цели, направление улучшения и штрафы берутся из текущих настроек. Отчёт только
читает данные; аналитические статусы не меняют конкурсные баллы и начисления.

## Чтение экрана

- Карточки и матрица относятся к последнему дню, неделе или месяцу выбранного диапазона.
  Диапазон целиком используется для графиков. Соседний предыдущий период — база сравнения.
- «Требуют внимания»: не выполнена хотя бы одна цель или есть положительное значение
  штрафного показателя. «Выполняют все цели»: загружены все активные показатели, все
  цели выполнены, нежелательных событий нет.
- «Есть ухудшение»: хотя бы один показатель стал хуже с учётом направления. Один
  оператор может одновременно иметь улучшения и ухудшения по разным показателям.
- Дисциплина использует настроенный `lateness_metric_code`. Отсутствие данных не
  означает отсутствие опозданий. В карточке показано число операторов, а не сумма случаев.
- Цветовая шкала: любое отклонение — внимание, от 10% относительно цели — риск,
  от 20% — сильное отклонение. Для «меньше — лучше» неблагоприятно превышение цели.
  При нулевой цели проценты не рассчитываются. Любое положительное значение
  штрафного показателя требует внимания, даже если укладывается в настроенный лимит.
- Разница между процентными значениями — процентные пункты. Относительное отклонение
  делится на цель: при цели 80 и факте 64 разница 16 п.п., отставание 20%.
- На круговой диаграмме каждый человек учитывается один раз: сильное отклонение,
  внимание, нет данных, неполные данные без отклонений или выполнение всех целей.
  Верхние карточки могут пересекаться по составу сотрудников.

## Данные и ограничения

Пустые наблюдения остаются `null`, включая историю. Полная карточка сотрудника
получает историю всех активных показателей в том же запросе и в той же области
доступа. Отдельного вычисленного общего «рейтинга здоровья» нет: сильное отставание
по одному показателю не скрывается средним или перевыполнением другого.

Существующая месячная агрегация сохранена: среднее недель, начинающихся в месяце,
а при отсутствии недельных записей — среднее дневных записей по оператору и метрике.
Это относится и к опозданиям; интерфейс явно предупреждает, что это не месячная сумма.
Настроенные цели общие для выбранных шагов; система не выводит новые дневные нормы
из недельных. Средние команды не взвешены по числу звонков или проверок.

Итоговые конкурсные баллы показываются только для рассчитанных или закрытых недель,
чтобы аннулированный расчёт открытой недели не выглядел актуальным.

## Проверки

`analyticsInsights.test.mjs`: границы 10/20%, направление метрики, нулевая цель,
пропуски, неполные наблюдения, смешанная динамика, приоритет и фильтры диаграммы.
`test_analytics_dashboard.py`: история всех показателей, серверные описания и штрафы,
отсутствие ложных нулей, скрытие устаревших баллов, пояснение месячной агрегации.
Дополнительно выполняются тесты периодов и существующих ограничений доступа.
