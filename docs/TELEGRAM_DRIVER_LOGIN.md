# Вход Driver Simulator через Telegram

Уточнение пользователя от 08.09.2026: после выбора парка сотрудник вводит
номер из своего профиля Puls, получает код в личном Telegram и подтверждает
браузер. Бот: **@puls_i_bot**. Обычный вход в Puls остаётся по логину и паролю.
Сценарии поддержки в этом обновлении не реализуются.

## Настройка сервера

В Render → **gamification-api → Environment** добавить:

| Переменная | Значение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен @puls_i_bot из BotFather; только в окружении API |
| `TELEGRAM_BOT_USERNAME` | `puls_i_bot` — без `@` |
| `TELEGRAM_WEBHOOK_URL` | `https://gamification-api-lbtb.onrender.com/api/v1/auth/telegram/webhook` |
| `DRIVER_DEVICE_DAYS` | `30` (это значение по умолчанию) |

Сохранить переменные и перезапустить API с опубликованным кодом. При обычном
автодеплое существующего Render-сервиса не следует полагаться на синхронизацию
новых ключей из `render.yaml`: добавьте их в Environment явно.

Команда запуска `alembic upgrade head` применяет миграцию
`20260908_driver_auth`. Она добавляет телефон сотрудника, привязки Telegram
и подтверждения браузеров. Старые сотрудники сохраняются без телефона;
заполнить их номера нужно через карточки пользователей.

При запуске API проверяет имя бота через `getMe` и регистрирует HTTPS-webhook
через `setWebhook`. Заголовок проверки webhook вычисляется из серверных
секретов автоматически. Отдельную публичную команду с токеном в URL запускать
не нужно. Telegram поддерживает этот заголовок и ответ на обновление непосредственно
через webhook. [Telegram Bot API: setWebhook](https://core.telegram.org/bots/api#setwebhook).

У одного бота один webhook: не используйте токен рабочего бота в тестовых
развёртываниях — они перенастроят его адрес. Если меняется `SECRET_KEY` или токен
бота, перезапустите API. Смена `SECRET_KEY` также делает прежние подтверждения
и личные ссылки недействительными.

Если настройки отсутствуют, обычный Puls продолжает работать. Новый вход
в Driver Simulator требует настройки бота; обхода с демонстрационным кодом нет.
При ошибке регистрации в журнале API появляется сообщение о настройке Telegram
без токена. Повторная регистрация происходит при следующем запуске сервиса.

## Подготовка сотрудника и вход

1. Руководитель или администратор открывает **Пользователи → сотрудник →
   Изменить** и сохраняет телефон с кодом страны. Поле также есть при создании
   аккаунта. Номера уникальны; `+7 (700) 123-45-67` сохраняется как `+77001234567`.
2. Сотрудник входит в Puls, открывает **Профиль → Telegram для входа →
   Подключить Telegram** и подтверждает действие своим паролем Puls.
3. По личной ссылке открывает @puls_i_bot и нажимает **Запустить**.
   Ссылка действует 10 минут и используется один раз. Она привязывает Telegram ID
   к текущему сотруднику, поэтому вводить изменяемый `@username` вручную не нужно.
   Формат ссылки соответствует [Telegram deep linking](https://core.telegram.org/bots/features#deep-linking).
4. Возвращается в Driver Simulator, выбирает парк и вводит свой номер.
   Шестизначный код приходит только в привязанный личный чат.
5. Вводит код → загрузка профиля → карта **Офлайн**. Этот браузер запоминается
   на 30 дней. В другом браузере или после удаления данных сайта нужен новый код.

Повторный запуск в подтверждённом браузере сохраняет выбор сервиса и парка в
сценарии, но пропускает ввод номера и кода. Подтверждение не заменяет сессию Puls.
Обычный выход из Puls сохраняет секрет браузера; повторный вход в тот же аккаунт
может использовать действующее подтверждение.

## Ограничения и отзыв

- Код действует 5 минут; после 5 ошибок его использовать нельзя.
- Повторная отправка — через 60 секунд, не более 5 кодов в час на сотрудника
  суммарно по браузерам. Новый код отменяет прежний для этого браузера.
- В базе хранятся HMAC-хеши кода, секрета браузера и одноразовой ссылки.
  Код не возвращается клиентскому API, не попадает в аудит и журналы приложения.
- Сервер проверяет подтверждение при чтении состояния и завершении входа.
  Сохранённый этап другого браузера или прямая ссылка не открывают карту.
- Смена телефона, пароля, перепривязка и отключение Telegram сбрасывают
  подтверждения. При архивировании также отзываются сессии Puls.
- Кнопка **Сбросить подтверждение этого браузера** находится в профиле
  Driver Simulator. Списки сессий и устройств остаются только у разработчика.
- Один личный Telegram нельзя привязать одновременно к двум аккаунтам Puls.
  При утрате Telegram можно подключить другой из своего профиля с паролем Puls.

Случайный секрет хранится в localStorage, как и существующая сессия Puls.
Это подтверждение браузера, а не аппаратная идентификация физического устройства.

## Проверки и границы готовности

- Серверные тесты проверяют весь путь, чужие номера и браузеры, одноразовые
  ссылки, Telegram ID, неверные коды, сроки, лимиты и отзыв подтверждений.
- Тесты клиента проверяют поля телефона/кода, состояния настройки, таймер
  повторной отправки и сохранение заголовка браузера при обновлении JWT.
- Проверены миграции SQLite upgrade → downgrade → upgrade и `alembic check`;
  SQL новой миграции сгенерирован для PostgreSQL.
- В изолированном Chrome проверены привязка, вход, ошибки номера и кода,
  повторный вход, потеря секрета, выход из Puls, смена парка и сброс подтверждения.
  Проверены ширины 320, 393 и 1440 px; скриншоты просмотрены. Использовалась
  локальная имитация Bot API и подписанного webhook, без реальных сообщений.
- Полный набор: 222 серверных теста; после исправления UTC повторно проверены
  тесты Telegram. Сборка и 43 клиентских теста прошли без ошибок.

**Для подтверждения рабочего запуска нужен токен на Render и один полный вход
с настоящим Telegram сотрудника. Локальная проверка не подтверждает доставку
через рабочий бот.**
