# Голосовой тренажёр сложных разговоров

Раздел «Обучение → Голосовой тренажёр» (`/training/voice`) содержит первый
сценарий смены номера телефона. Участник выбирает спокойного, растерянного,
торопящегося или раздражённого водителя. Учебные данные вымышленные.

Оператор проверяет микрофон, запускает звонок и отвечает по очереди: «Ответить» →
«Завершить запись» → проверка распознанного текста → «Отправить ответ».
Можно отредактировать текст или перезаписать его. В браузере без распознавания,
при запрете микрофона и при ошибке голосового сервиса доступен текстовый ответ.
Кнопка повтора воспроизводит последнюю реплику водителя. Микрофон и озвучка
отключаются отдельно; при уходе со страницы голосовые ресурсы освобождаются.

Распознавание и синтез используют Web Speech API браузера с языком `ru-RU`.
Распознавание может обращаться к голосовому сервису поставщика браузера и требовать
Интернет. Сервис Puls не записывает и не хранит аудиофайлы: на API отправляется
проверенный оператором текст. Для микрофона нужен HTTPS (localhost допускается
браузером). Наличие конкретного русского голоса зависит от браузера и ОС.

## Разговор и учебные системы

Решение до завершения не раскрывается. Водитель реагирует на содержание реплик,
сообщает об утрате старой SIM-карты и просит доступную альтернативу. Названия
канала недостаточно: нужно объяснить конкретное действие. Растерянный водитель
просит упростить объяснение, торопящийся — выбрать один первый шаг,
раздражённый — объяснить причину ограничения.

Диспетчерская и CRM используют существующие учебные аккаунты. Оператор сам
находит нужного водителя. Просмотр засчитывается только после отображения вкладки
«Подробнее» правильного аккаунта в его парке. Во вкладке OKTEL есть карточка
входящего учебного звонка данной попытки и явное подтверждение чтения данных.
После двух просмотров оператор вводит номер регистрации из аккаунта и сравнивает
его с номером звонка. Сервер проверяет аккаунт, парк и оба номера и сохраняет
события. Заявление «я всё проверил» в разговоре эти события не заменяет.

Доступ к рабочим сайтам и API наблюдений сохраняет существующее QR-подтверждение.
Сам голосовой разговор доступен по праву «Обучение» оператора и стажёра, у сотрудников —
по праву управления обучением. Для тренажёра не требуется назначение группы городу ТП.

Попытка привязана к аккаунту и своей версии правил. При переходах между системами
её ID сохраняется в `voiceAttempt`. Перезагрузка восстанавливает отправленные
реплики с сервера, черновик текущей реплики — из sessionStorage в том же браузере.
Идентификатор запроса и номер хода защищают от повторной отправки и устаревшей вкладки.

## Оценка и наставник

Правила основаны на согласованном учебном курсе CRM v2 (`crm_mismatch_v2`,
[программа CRM](CRM_TRAINING.md)) и требованиях голосового сценария.
Это ограниченный пилот с детерминированным распознаванием смысловых конструкций,
а не универсальная языковая модель. Незнакомая формулировка может потребовать
уточнения. Интонация, темп, акцент и эмоции голоса не оцениваются.

После «Завершить тренировку» сервер оценивает четыре критерия по 25 баллов:
проверку данных, правильность решения, понятность причины и конкретный следующий
шаг. Решение учитывает три допустимых способа из учебной программы: позвонить с
номера регистрации, изменить номер в приложении («Такси Про»), обратиться в
WhatsApp. После утраты SIM нужна оставшаяся альтернатива. Прямое обещание оператора
сменить номер по текущему звонку — отдельная критическая ошибка; итог при её
наличии ограничен 50 баллами. Отрицание «не могу поменять» само по себе ошибкой
не является.

В разборе показаны цитаты и примеры улучшения. Повтор проблемного момента создаёт
новую попытку с предшествующим разговором; исходная остаётся в истории.
Проверенные действия до выбранного момента сохраняют ссылку на исходную попытку.

Оператор может сохранить пояснение к спорной оценке. Запрос попадает в очередь
«Спорные оценки» в том же разделе у наставника. Супервайзер видит только свои
действующие группы, остальные сотрудники — в пределах видимости их роли.
Наставник открывает расшифровку и сохраняет ответ; он отображается в разборе
оператора. Проверка не переписывает исходный автоматический балл.

## Обновление и проверки

Миграция `20261017_voice_training` создаёт таблицу `voice_training_attempts`.
Перед запуском новой версии API выполняется обычное `alembic upgrade head`;
фронтенд и API должны обновиться совместно. Новых ключей внешних сервисов и
пакетов для голосового сценария не требуется. Новые правила следует выпускать с
новой ревизией, сохраняя оценку старых попыток воспроизводимой.

Проверки: `tests/test_voice_training.py` (сценарий, отрицания, события, история,
владение попытками, QR, повтор хода и очередь наставника), `tests/test_access.py`,
клиентские проверки навигации и `voiceTraining.test.mjs` (API, контекст, разбор),
`useVoiceSpeech.test.mjs` (разрешения, запись,
распознавание, озвучка и освобождение ресурсов). Реальный голос и микрофон
дополнительно проверяются на целевых устройствах операторов.

Дальнейшие сценарии — повторное обращение по тикету и доработка после ООЗ —
не включены в первую версию. Непрерывный разговор с перебиваниями потребует
отдельной реализации потокового аудио.
