# Сессии и устройства

Раздел `/admin/sessions` доступен только учётной записи разработчика, определённой
серверной конфигурацией. Назначаемые роли и права на разделы не дают доступа к
управлению сессиями. Роль в фильтре означает роль сотрудников, чьи входы выбираются.

## Действия

- Завершить один вход на конкретном устройстве.
- Отметить несколько входов и завершить выбранные.
- Завершить сеансы, показанные текущими фильтрами.
- Завершить входы выбранного сотрудника на всех устройствах.
- Завершить входы сотрудников выбранной роли.
- Завершить все показанные в общем списке активные входы.
- Завершить свои другие сеансы.

Поиск учитывает имя, логин, IP-адрес, браузер и платформу. Отбор по роли сочетается
с сотрудником, платформой и давностью активности. При изменении фильтров выбор строк
сбрасывается, чтобы скрытые строки не попали под массовое действие.

Перед отправкой открывается подтверждение с областью действия, количеством сеансов
и сотрудников. Список идентификаторов фиксируется при открытии подтверждения:
появившийся после этого вход в действие не включается. Для него нужно обновить
список и открыть новое подтверждение. Текущая сессия защищена по умолчанию;
для её завершения нужно явно снять соответствующую отметку.

Завершение отзывается на сервере: access- и refresh-токены перестают приниматься.
На следующем запросе с устройства потребуется повторная авторизация. Это не
блокировка аккаунта и не запрет повторного входа с правильными учётными данными.

## API и проверка границ

`GET /api/v1/admin/sessions` возвращает активные неистёкшие сессии, включая логин,
имя и актуальную роль владельца. Секреты и хеши токенов не возвращаются.

`POST /api/v1/admin/sessions/revoke-bulk` принимает:

```json
{
  "scope": "role",
  "role": "operator",
  "session_ids": ["подтверждённый идентификатор сессии"],
  "keep_current": true
}
```

Области: `selected`, `user` (с `user_id`), `role` (с `role`), `all`.
Всегда требуется непустой список уникальных `session_ids` из подтверждения,
не более 5000. Несогласованные критерии и неизвестные поля отклоняются.
Сервер пересекает список с текущими активными сессиями и выбранным сотрудником
или ролью. Изменившаяся роль проверяется заново при выполнении.

Ответ содержит `revoked_count`, `user_count`, `current_revoked` и `detail`.
Уже завершённые, истёкшие и не относящиеся к выбранной области сессии не
засчитываются. Повторный запрос не увеличивает количество отозванных сеансов.
Результат записывается в аудит как `session.revoke_bulk` с критериями и фактическими
счётчиками. Доверие браузерам для входа водителей через Telegram не изменяется:
массовое действие затрагивает только подтверждённые сеансы.

Миграции БД для изменения не требуются. В интерфейсе используется тот же
контроль доступа разработчика, что и в API.
