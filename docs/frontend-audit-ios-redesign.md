# Аудит frontend и iOS/iPadOS-редизайн Puls

Дата аудита: 31 июля 2026 года. Область: единый SPA из `index.html`, `js/src`, `css/src`; роли `admin`, `manager`, `supervisor`, `operator`.

## Карта ролей и маршрутов

| Роль | Основные маршруты |
| --- | --- |
| Администратор | Сводка, Пользователи, Аналитика, Коины, Рейтинг, Уровни, Группы, Расчёт периода, Сессии, Тесты, Миссии, Wheel of WOW, Розыгрыши, Магазин, Кабинет |
| Менеджер | Сводка, Пользователи, Аналитика, Коины, Рейтинг, Уровни, Группы, Расчёт периода, Тесты, Миссии, Wheel of WOW, Розыгрыши, Магазин |
| Супервайзер | Сводка, Пользователи своей области, Аналитика, Коины, Рейтинг, Расчёт периода, Тесты, Миссии, Wheel of WOW, Розыгрыши, Магазин, Кабинет |
| Оператор | Кабинет, Рейтинг, Миссии, Тесты, Магазин, Wheel of WOW, Розыгрыши |

Доступ к маршруту повторно проверяется при прямом открытии, F5, `Back` и `Forward`. Недоступный маршрут заменяется стартовым маршрутом роли. Критические права по-прежнему проверяет backend; frontend только скрывает недоступные действия и не является границей безопасности.

## CSS-аудит

До очистки было 27 CSS-файлов (около 470 КБ и 13 270 строк), 284 повторяющихся селектора, 238 применений `!important`, внешняя загрузка Google Fonts и четыре поздних глобальных слоя, конкурировавших за sidebar, таблицы, кнопки, modal и mobile layout.

Новая структура последнего каскадного слоя:

- `00-foundation.css` — reset, типографика, keyboard focus, reduced motion;
- `10-layout.css` — shell, container, grid, page header;
- `20-navigation.css` — sidebar, compact mode, mobile tab bar и sheet;
- `30-components.css` — buttons, cards, KPI, tabs, badges, progress;
- `40-forms.css` — поля, labels, select, switches и validation;
- `50-tables-charts.css` — desktop table region, mobile cards и charts;
- `60-states-overlays.css` — loading/empty/error, modal, toast;
- `70-view-harmonization.css` — приведение legacy views к системе;
- `80-responsive.css` — согласованные breakpoint и safe-area правила;
- `90-utilities.css` — минимальный набор атомарных утилит.

Семантические значения определены в `css/tokens.css`; view-specific стили остаются раньше системного слоя и не создают второй frontend.

Удалены конфликтующие legacy-слои `90-visual-polish.css`, `zz-corporate-trust-system.css` и `zzz-ui-ux-hardening.css`. Глобальный хвост `20-rating-shop-dashboard.css` удалён, оставлены только стили самого рейтинга. Старый смешанный `40-coins-tests-wheel-overrides.css` без изменения порядка правил разделён на `40-coins.css`, `41-tests.css`, `42-levels-users.css`, `43-rating-dynamics.css`, `44-wheel.css`, `45-sessions.css` и `46-wheel-admin-refinement.css`.

## Данные и бизнес-ограничения

Формулы, API URL, backend-поля, начисления и ролевые правила не менялись. Настройка видимых столбцов и настоящая серверная пагинация могут быть добавлены только там, где backend даст соответствующие параметры; frontend не имитирует их на выдуманных production-данных.

## Результаты проверки

| Проверка | Результат |
| --- | --- |
| `npm run build` | Успешно; 6 API-, 26 app- и 40 CSS-source файлов собраны |
| `npm run check:minified` | Успешно; API −45%, app −22%, CSS −18% |
| `npm test` | 54/54 успешно |
| `npm audit --audit-level=high` | 0 уязвимостей |
| `ruff check app tests scripts` | Успешно |
| `python -m compileall -q app scripts tests` | Успешно |
| `pytest -q` | 277 успешно, 2 сторонних deprecation warning |
| HTTP production smoke | SPA/assets 200; вход для четырёх ролей; семь operator API 200; запрещённый `/api/users` 403 |

`ruff format --check app` выявил 85 давно неформатированных backend-файлов. Они не были массово переписаны в frontend-задаче: это изменило бы практически весь backend вопреки ограничению ТЗ не трогать его без необходимости. Линтер и все backend-тесты проходят.

В окружении выполнения не предоставлен доступный экземпляр встроенного браузера (`agent.browsers.list()` вернул пустой список). Поэтому автоматизированные визуальные скриншоты по матрице разрешений не выдаются за выполненные. Вместо этого выполнены source-contract, build, responsive/a11y regression и живой HTTP/API smoke; ручной визуальный проход остаётся обязательной release-проверкой на реальном браузере.
