# План реализации UX-аудита Puls

**Дата:** 7 октября 2026 года.

**Основание:** [зарегистрированное ТЗ](UX_AUDIT_2026_10_06_TZ.md), предоставленный `Claude Code.pdf`.

**Текущий статус:** план подготовлен; продуктовые изменения по нему не выполнялись.

**Базовая ревизия для сверки кода:** `bf21d18`, версия 2.24.9.

## 1. Принцип выполнения

Сначала закрыть риски ошибочных финансовых действий и неверной информации, затем общую доступность и навигацию, после этого учебные и управленческие сценарии. Выполнять этапы небольшими проверяемыми изменениями. Сроки и исполнителей назначить при начале реализации: формулировка аудита «за день» не является оценкой всей работы.

Номера #1–#27 и M01–M09 связаны с критериями приёмки в ТЗ. Наличие отдельных существующих функций не закрывает весь пункт. Проценты, рейтинговые места, состояния аккаунтов и численные измерения из PDF не принимать за текущие производственные данные.

## 3. Этапы

### Этап 0. Подготовить воспроизводимую проверку

- Снять исходное поведение на локальном тестовом стенде для оператора, супервайзера и руководителя; дополнить проверки администратора и тренера для сквозных компонентов.
- Использовать тестовые данные: новичок, опытный оператор, несколько групп, опубликованная/текущая неделя, скрытый победитель, активная заявка и частично зарезервированный кошелёк.
- Матрица экранов: 1440×900, 1280×900 и 390×844; светлая/тёмная тема; клавиатура, touch, скринридер, увеличение текста, `prefers-contrast: more`.
- Сохранить существующие проверки прав и экономики как регрессионные ограничения. Операции с реальными коинами не использовать для визуальной проверки.
- Перед отдельными этапами закрыть соответствующие решения из раздела 5 ТЗ; вопросы не блокируют регистрацию плана.

**Ожидаемый результат:** исходные сценарии, фикстуры и проверяемые критерии; статус — запланировано.

## 5. Завершение каждого этапа

- Есть список выполненных ID и доказательства соответствия критериям: автоматические проверки и нужные ручные сценарии.
