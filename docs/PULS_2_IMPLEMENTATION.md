# Puls 2.0 — реализация

Это первичный план работ. Актуальные результаты и остаток ТЗ на 06.09.2026:
[PULS_2_STATUS.md](PULS_2_STATUS.md).

Источник требований: Design Specification 1.0, предоставленная 05.09.2026.
Работа ведётся поверх существующего FastAPI + React MVP. Галочка означает
реализацию и проверку, а не наличие ссылки или макета.

## Очерёдность

1. Корректность данных и прав; мобильный shell и доступность primitives.
2. Пользователи, группы, импорт CSV/XLSX, проверка, расчёт и публикация периода.
3. Сессии и аудит; настройки, кошелёк, независимый XP и уровни.
4. Аналитика: сводка, операторы, качество, сравнения и история.
5. Обучение: тесты, миссии, студии и прогресс.
6. Driver Simulator и редактор сценариев.
7. Магазин, колесо, розыгрыши, уведомления.
8. PWA, полная матрица состояний и визуальная проверка.

## Текущий проход

- [ ] Отсутствующее значение отдельно от нуля, без начисления баллов за пропуск.
- [ ] Ограничение загрузки/замены показателей группами супервайзера.
- [ ] Mobile sidebar offset, полный доступ к навигации, доступные modal/sheet.
- [ ] Пользователи, группы и карточка сотрудника с ролевыми правами.
- [ ] Предварительный разбор CSV/XLSX без записи, ошибки по строкам.
- [ ] Экран периода: файл → проверка → preview → расчёт → публикация.
- [ ] Серверные сессии и их отзыв, UI управления сессиями.
- [ ] Просмотр аудита с фильтрами и человекочитаемыми изменениями.
- [ ] Регрессионные проверки расчёта, изоляции прав и новых сценариев.

## Уточнения

Дизайн-ТЗ задаёт пользовательские сценарии и внешний вид. Новые экономические
правила (XP, награды обучения и игр) должны быть настраиваемыми. Ранее заработанные
коины и закрытые результаты не меняются молча при переходе к независимому XP.
Существующая модель периода — ISO-неделя; расширение на произвольный период
требует явной модели периода и не маскируется переименованием в интерфейсе.

Полное ТЗ пока не выполнено. Дальнейшие блоки остаются в этом плане до проверки.
