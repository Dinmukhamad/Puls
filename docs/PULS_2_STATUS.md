# Puls 2.0 — реализация и оставшаяся работа

Обновление 2.1.0: Driver Simulator расширен до связанных смен, пяти разделов,
проверок автомобиля, учебной экономики, Telegram-поддержки и итоговой оценки.
[Реализация, сценарий, настройка и ограничения](DRIVER_SHIFTS.md).

Состояние на 09.09.2026. Основа: существующий FastAPI + React MVP и предоставленная
Design Specification 1.0 (`PULS_2.0_Design_TZ_iOS26.docx`). Текст требований сохранён
в `PULS_2_DESIGN_SOURCE.txt`. Документ задаёт дизайн и сценарии; отдельные новые
формулы экономики в нём не определены. Они не подменяются демонстрационными числами.

Дополнение пользователя «Структура разделов Puls» принято как актуальная структура
навигации. [Исходное ТЗ](PULS_2_SECTIONS_SOURCE.md),
[блоки и состояние реализации](PULS_2_SECTIONS_IMPLEMENTATION.md).

Уточнение оператора от 07.09.2026: кабинет упрощён, показатели собраны в
раскрывающиеся группы, личный кошелёк работает без фильтров, опыт и уровни
перенесены в «Результаты», прежний экран графиков личного рейтинга удалён.
[Подробности и открытый вопрос о шкале оценки за звонки](OPERATOR_UI_2026_09_07.md).
Эти указания заменяют прежние требования к удалённым блокам и графикам.

По уточнению от 09.09.2026 Driver Simulator расширен до полного повторяемого
заказа: введённые адреса → линия → подача → ожидание → поездка → оплата →
результат. Оплата случайно наличными или картой. [Сценарий и сохранение](DRIVER_ORDERS.md).
[Ранее реализованный вход](DRIVER_SIMULATOR_PREVIEW.md) сохранён.

По уточнению от 08.09.2026 добавлены номер из карточки сотрудника, привязка
@puls_i_bot, код из Telegram и подтверждение браузера на 30 дней. Для рабочей
доставки нужен токен бота в окружении Render и проверка настоящим сотрудником.
[Настройка и ограничения](TELEGRAM_DRIVER_LOGIN.md).

## Важные свойства текущей реализации

- Отсутствующее значение метрики отличается от фактического нуля и не даёт баллы за пропуск.
- Повторная публикация недели и повторное начисление XP/учебной/игровой награды не дублируют операцию.
- Учебная попытка хранит снимок материала и наград. Изменение материала не меняет уже начатую попытку.
- Награда за обучение выдаётся за первое успешное прохождение материала, повторения бесплатны и без повторной награды.
- Колесо по умолчанию выключено. Лимит вращений обновляется в 00:00 UTC. Участие в играх не списывает коины.
- Условия розыгрыша с участниками не редактируются. Победитель выбирается сервером с равными шансами, повторное проведение сохраняет результат.
- Фото и GPS симулятора не отправляются в API и не сохраняются в истории. Адресные подписи новых заказов сохраняются на сервере для восстановления и личной истории; реальный маршрут по ним не строится. Номер для входа теперь сохраняется в карточке сотрудника и проверяется сервером; коды идут в его привязанный Telegram. Карта OpenStreetMap получает область просмотра непосредственно от браузера; это объясняется перед включением геолокации.
- Поддержка и SMS симулятора учебные, реальные сообщения не отправляются.
- Аналитика использует имеющиеся недельные значения. Дневные оценки и число проверок не выдумываются.
- Wallet считает начисления, списания и возвраты за выбранные даты; баланс и резерв показывают текущее состояние. Фильтр типа влияет на историю, но не меняет KPI периода. Границы дат заданы по UTC.
- Повторная ручная операция с тем же `request_id` возвращает прежний результат; изменение суммы, причины или получателя с этим ключом отклоняется. Старые API-клиенты без ключа продолжают работать без этой гарантии.
- Основной уровень кабинета использует XP. Прежние ступени по накопленным коинам удалены отдельным обновлением `a1c4d9e07b32`.
- Управленческие роли по умолчанию видят рабочую сводку и командные функции. Личный кабинет, XP/кошелёк, прохождение обучения и покупки включаются отдельно. Права разделов не расширяют роль и область данных. Настройка: [SECTION_ACCESS.md](SECTION_ACCESS.md).
- В раскрывающихся показателях кабинета отсутствие данных даёт прочерк в баллах; фактический ноль остаётся нулём. Прежняя отдельная история графиков рейтинга удалена из интерфейса.
- Время операций корректно переводится из UTC и при ответах SQLite без суффикса часового пояса.

## Проверка и публикация

Сервер: `pytest -q -p no:cacheprovider` и `ruff check .`.
Интерфейс: `npm test` (TypeScript, production build, проверки API-клиента и service worker).
Миграции: `alembic upgrade head` и `alembic check` на отдельной SQLite-базе.
Перед публикацией обновления профиля и доступа разработчика прошли 146 серверных тестов и 22 теста клиента/PWA, TypeScript,
production build и Ruff. Для PostgreSQL дополнительно сформирован SQL всех миграций
в offline-режиме; запуск миграций на живом PostgreSQL локально не выполнялся.
Визуальная проверка пока не выполнена: ранее открытие браузера было отклонено автоматической
проверкой разрешений из-за лимита использования; при повторной проверке окружение
не предоставило доступных браузеров. Это не считается подтверждением
responsive, камеры, GPS, жестов или установки PWA на реальных устройствах.

После уточнений кабинета от 07.09.2026 прошли 191 серверный тест и 31 клиентская
проверка, TypeScript, production build и Ruff. В этом обновлении миграций нет;
вопрос шкалы новой оценки за звонки остаётся открытым.

Полный заказ Driver Simulator от 09.09.2026: 236 серверных и 62 клиентских теста,
Ruff, TypeScript, production build, миграции и проверка полного пути в Chrome
с наличными/картой, восстановлением, потерей сети и повтором заказа прошли.
[Подробности сценария и границы проверки](DRIVER_ORDERS.md).

Публикация текущего объёма в `main` отдельно разрешена пользователем 06.09.2026.
Полное выполнение дизайн-ТЗ не заявляется; оставшиеся пункты перечислены выше.

## Обновление существующей установки

1. Установить зависимости (`openpyxl` нужен для XLSX).
2. Выполнить `alembic upgrade head` перед запуском приложения. Новые миграции добавляют
   сессии, XP/уведомления, обучение, игры и правила доступа; история коинов сохраняется.
3. Пользователи входят заново: прежние JWT без идентификатора серверной сессии отклоняются.
4. XP не вычисляется из старого баланса. При включённом `SEED_REFERENCE_DATA` стартовые
   уровни XP создаются только для пустого справочника.
5. Обучение публикуется через студию; рабочие правила колеса и розыгрыши настраивает руководитель.
6. Для кошелька, XP в карточках и графиков рейтинга дополнительных миграций поверх
   уже опубликованных сессий/XP/обучения/игр не требуется.
7. Для настраиваемого доступа обязательна миграция `20260906_access`. В Render
   `alembic upgrade head` уже входит в команду запуска. Администратор управляет
   правилами через «Система → Доступ к разделам».
8. Сессии и устройства доступны только разработчику: `DEVELOPER_LOGIN=admin`
   соответствует аккаунту владельца на предоставленном скриншоте. Другая роль admin
   не даёт это полномочие; настройка меняется только на сервере. Профиль стал компактнее,
   повторные ссылки и пустые поля убраны. Это обновление не требует новой миграции.
9. Для нового входа Driver Simulator нужна миграция `20260907_driver`.
   Парки настраиваются в «Студия обучения → Driver Simulator».
10. Подтверждение через Telegram требует миграции `20260908_driver_auth` и трёх
    переменных окружения из [инструкции](TELEGRAM_DRIVER_LOGIN.md). Поддержка в боте — будущий этап.
11. Полный учебный заказ требует миграции `20260909_driver_orders`.
    [Условия сценария, хранение данных и проверки](DRIVER_ORDERS.md).

Справка провайдера карты: [OpenStreetMap Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/).
Используются только видимые тайлы, обычный браузерный HTTP-кеш и видимая атрибуция;
офлайн-загрузка карты в PWA отсутствует.
