# Демо-данные для показа сайта

Скрипт `scripts/seed_demo_season.py` заполняет сентябрь и октябрь у всех активных операторов,
чтобы сайт выглядел живым. Потом всё убирается одной командой.

## Что появляется

- Показатели по дням и за неделю — с 31.08 по вчерашний день, каждому оператору по его
  направлению (линия или чаты). Неделя 31.08 – 06.09 относится к сентябрю, по четвергу.
- Баллы, места и номинации недель. Закрытые недели остаются закрытыми, текущая показывает
  предварительный расчёт.
- Рейтинг месяцев (сентябрь и октябрь) — места и номинации.

Каждую неделю все цели выполняют примерно каждый десятый оператор, и каждый раз другие, поэтому
в рейтинге есть и лидеры, и середина, и отстающие. Числа зависят только от недели и оператора:
повторный запуск даёт те же значения и ничего не дублирует.

## Чего нет и почему

- **Коинов.** Журнал коинов неизменяем: начисление нельзя удалить даже в базе. Поэтому коины в
  демо-результатах обнулены, операций в журнале нет, балансы не меняются.
- **Уведомлений.** Операторам ничего не приходит — ни на сайте, ни в Telegram.
- **Посторонних сайтов.** Их отмечают руководители (`services/violations.py`), поэтому в демо
  они только настоящие. Где записей нет, расчёт недели ставит 0, как и для настоящей недели.
- **Обучения и города.** Пройденная миссия даёт награду, которую оператор забирает сам, и эти
  коины потом уже не удалить.

## Настоящие данные не трогаются

- Демо-значения ставятся только туда, где своих нет: источник `demo`
  (`app/models/contest.DEMO_SOURCE`).
- Если у оператора за неделю есть настоящие дневные показатели (отчёт СЗоВ за сентябрь), его
  дни не дополняются. Недельное значение берётся из настоящих дней: штуки и нарушения
  складываются, проценты и «в час» усредняются. Демо добавляет только недостающие показатели.
- Тестовую неделю (`scripts/seed_test_week.py`) скрипт не трогает: если в этих неделях есть
  тестовые значения, он останавливается и просит сначала удалить их.

## Защита от настоящих коинов

Пока демо-данные лежат в базе, неделю или месяц с ними закрыть нельзя: закрытие начисляет коины.
Это проверяет `services/weekly.refuse_demo` в `close_week` и в `months.close`. Автоматическое
закрытие по понедельникам считает демо-значения не работой (`has_work_data`) и оставляет такую
неделю открытой, а не падает с ошибкой. Сайт отвечает: «В
неделе есть демо-данные… Сначала удалите их». Поэтому перед обычным закрытием недели демо нужно
удалить, а перед загрузкой настоящего отчёта — тоже.

## Запуск

Render → `gamification-api` → Shell:

```
python -m scripts.seed_test_week 2026-10-05 --remove   # если тестовая неделя ещё есть
python -m scripts.seed_demo_season                     # заполнить
python -m scripts.seed_demo_season --remove            # удалить всё демо
```

## Удаление

Удаляются все строки с источником `demo`. Недели пересчитываются по оставшимся настоящим
данным, и им возвращается прежний статус. Его каждый результат хранит в
`breakdown["demo"]`, повторный запуск сохраняет самый первый. Нули «без посторонних сайтов», которые
дописал расчёт демо-недель, тоже удаляются. Записи руководителей остаются. Неделя, которую завёл
сам скрипт (текущая), удаляется целиком. Месяцы пересчитываются.

Проверка: `tests/test_demo_season.py`.
