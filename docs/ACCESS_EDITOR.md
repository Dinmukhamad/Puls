# Настройка доступа к разделам

Экран доступен администратору. Слева выбираются получатели: одна или несколько
ролей, рабочие группы, до 200 сотрудников либо общее правило для всех.
Справа — разделы, поиск, тумблеры, источник настройки и итоговый доступ аудитории.

Тумблер создаёт черновик. Изменённые разделы отмечаются, внизу появляется перечень
изменений с кнопками сохранения и отмены. Пока есть черновик, получатели закреплены.
Возврат тумблера к исходному состоянию отменяет изменение, не создавая лишнего
исключения. Можно отменить один раздел или весь черновик.

Если настройки выбранных получателей различаются, тумблер показывает «Разный
доступ». Включение создаёт разрешение на выбранном уровне; выключение — запрет.
«Вернуть наследование» удаляет только выбранные исключения. Личное правило важнее
группы, группа важнее роли, роль важнее общего правила. Ниже — настройки роли
по умолчанию. Правила роли и группы применяются также к будущим участникам.

Предпросмотр различает правило роли и фактический результат: например, выключенное
обучение у роли может оставаться открытым сотруднику с личным разрешением. Экран
показывает число аккаунтов с доступом до и после сохранения и количество более
точных исключений. В число аккаунтов включаются неактивные. Для пустых групп
показываются наследуемые настройки возможных ролей без выдуманного числа людей.

`POST /api/v1/admin/access/preview` использует тот же resolver, что и действующая
авторизация. Он не записывает правила, аудит или ревизию. Входные данные и ревизия
проверяются; изменение прав остаётся в `PUT /api/v1/admin/access` с аудитом и защитой
от конкурентного сохранения. Предпросмотр не обходит административные ограничения.
Сессии и устройства по-прежнему доступны только разработчику и не назначаются здесь.

При конфликте сохранение блокируется, черновик сохраняется. Кнопка загрузки
актуальных правил явно сбрасывает его. Успех и ошибки показываются внутри экрана.

Проверки: тесты API наследования, массового выбора, пустых групп, ревизий,
отсутствия побочных записей и прав разработчика; frontend-тесты черновика и тумблеров.
В локальном браузере с настоящим API и отдельной тестовой базой проверены сохранение,
отмена, личные исключения и конфликт двух окон; узкая раскладка и обе темы.
