# Driver Simulator: интерфейс 2.2.1

## Поведение элементов

- Жёлтая кнопка выполняет действие; рядом с прибытием, началом и завершением
  объясняется следующий этап. Причина недоступности действия остаётся в панели.
- Переходы в адреса и поддержку названы «Выбрать…» / «Открыть…» и отмечены стрелкой.
- Справка по GPS и детали заказа раскрываются с `+` / `−`; инструкция не обещает
  открыть настройки браузера или телефона автоматически.
- Вход начинается с заполненного `+7`; одного префикса недостаточно для запроса кода.
- Сообщение пассажиру не использует поле поиска адреса. Текст очищается после
  появления ответа в состоянии смены, а при ошибке остаётся для повторной отправки.
- Учебный звонок явно назван симуляцией. Подготовка обращения отделена от ссылки
  «Открыть Telegram», которая появляется после ответа сервера.
- «Моя смена» в чатах открывает разбор смены. Способ оплаты и провайдер ЭДО
  используют радиокнопки; скрытие подсказки не вызывает штрафное действие.
- При потере GPS панель открывается минимум наполовину, после завершения также
  раскрывается результат. Компактная панель имеет минимальную высоту 190 px.
- Шрифт симулятора: Segoe UI / Roboto / Helvetica Neue / Arial; базовый размер
  16 px, пояснения и раскрываемые детали — 14 px.

## Проверка

`npm --prefix frontend test`: production-сборка и 74 теста.
Добавлены проверки телефона, GPS-блокировок, объяснений прибытия/оплаты,
перехода в результат смены и групп радиокнопок.

Изолированные браузерные проверки React-компонентов с тестовыми ответами API:
ввод телефона и запрос кода, раскрытие справки без команды заказа, повторный
запрос GPS, однократная отправка завершения и показ результата, переход из чатов.
Вёрстка проверена в узких контейнерах 320/393 px и настольном окне.
Эти проверки не заменяют испытание реального GPS и Telegram на телефоне.

Локальные проверочные страницы, логи и скриншоты находятся в игнорируемой `.qa/`.
